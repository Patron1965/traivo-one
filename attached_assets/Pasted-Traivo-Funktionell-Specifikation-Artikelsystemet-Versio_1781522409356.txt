1. EXECUTIVE SUMMARY
1.1 Vad är artikelsystemet i Traivo
Artikelsystemet är den centrala modulen i Traivo för att definiera, konfigurera och hantera alla typer av artiklar (tjänster, produkter, material) som används i operativ verksamhet. Systemet hanterar hela livscykeln från artikelupplägg (integrerat med Fortnox) till prissättning, lagerhantering, planeringslogik, strukturartiklar (BOM — Bill of Materials), automatisk association via metadata-villkor, antalsberäkningar och informationsinsamling i fält.

1.2 Syfte och målgrupper
Målgrupp	Användning
Administratör/Back-office	Skapar och konfigurerar artiklar, definierar BOM-strukturer, sätter priser och associationsvillkor
Fältarbetare	Konsumerar artikelinformation, rapporterar antal, uppdaterar metadata vid utförande
Ekonomi/Controller	Övervakar priser, marginaler, Fortnox-synk
Systemintegratör	Kopplar Fortnox, metadata-katalog, lager

4. DATA MODEL & RELATIONSHIPS
4.1 Artikelschema (Article)
typescript
Copy
interface Article {
  // === Grunddata ===
  id: string;                          // UUID, auto-generated
  organizationId: string;              // FK → Organization
  artikelnummer: string;               // UNIQUE per organizationId. Synkad från Fortnox.
  namn: string;                        // Max 50 tecken. Required.
  status: 'aktiv' | 'inaktiv';        // Default: 'aktiv'
  enhet: string;                       // Från Fortnox, t.ex. "st"
  artikeltyp: string | null;          // FK → ArticleType (sidoregister)
  kundbeskrivning: string | null;      // Visas externt (fakturor)
  internBeskrivning: string | null;    // Visas internt (utförare)

  // === Fördjupad info ===
  filer: ArticleFile[];                // Uppladdade filer
  externLank: string | null;           // URL

def berakna_marginal(article):
    """Real-time beräkning vid varje fältändring"""
    marginal = article.listpris_kr - (article.inkopspris_kr + article.materialkostnad_kr)
    return marginal  # Formateras som "+X,XX kr" eller "-X,XX kr"
Uppdateras vid ändring av listprisKr, inkopsprisKr, eller materialkostnadKr.

def berakna_offset_minuter(enhet, varde, typ):
    """Konverterar offsettid till minuter relativt huvudjobb"""
    minuter = varde if enhet == 'minuter' else varde * 24 * 60
    
    if typ == 'before':
        return -minuter
    elif typ == 'simultaneous':
        return 0  # Ignorerar värde
    elif typ == 'after':
        return +minuter

def matchar_villkor(article, objekt):
    """Kontrollerar om ett objekt matchar artikelns fasthakningsvillkor (AND-logik)"""
    if not article.fasthakningsvillkor:
        return False  # Inga villkor = ingen automatisk association
    
    for villkor in article.fasthakningsvillkor:
        objekt_varde = objekt.metadata.get(villkor.metadata_field)
        
        if villkor.operator == 'equals' and str(objekt_varde) != str(villkor.value):
            return False
        # ... övriga operatorer
    
    return True  # Alla villkor uppfyllda

def kontrollera_cirkularitet(parent_id, child_id, visited=None):
    """Förhindrar cirkulära BOM-referenser"""
    if visited is None:
        visited = set()
    
    if child_id == parent_id:
        raise ValidationError("Cirkulär BOM-referens upptäckt")
    
    if child_id in visited:
        return  # Redan kontrollerad
    
    visited.add(child_id)
    
    child_article = get_article(child_id)
    for komponent in child_article.bom_komponenter:
        kontrollera_cirkularitet(parent_id, komponent.child_article_id, visited)

9.3 Optimistic updates vs server validation
Client-side: Inline validation (required, format, max length) — omedelbar feedback.
Server-side: Unique constraints (artikelnummer), BOM-cirkularitet, Fortnox-synk.
Save-strategi: Hela formuläret sparas vid explicit "Spara"-åtgärd (ej auto-save per sektion).
9.4 File upload handling
1. Användaren dropar/väljer fil
2. Client validerar: filstorlek ≤ 20 MB, tillåten MIME-typ
3. POST till upload-endpoint (multipart/form-data)
4. Server returnerar { fileId, url, filename }
5. fileId lagras i artikelns filer-array
6. Visa filnamn + ta bort-knapp i UI
