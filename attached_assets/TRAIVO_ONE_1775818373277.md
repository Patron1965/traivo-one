## 1. Översikt & Vision

### Vad är Traivo One?

Traivo One är ett **enterprise-fältsystem** byggt för att ge små, medelstora och stora bolag ett komplett verktyg för fältverksamhet. Systemet hanterar hela kedjan från planering och ruttoptimering till fältexekvering, uppföljning och kundkommunikation.

**Ruttoptimering är en av flera kärnfunktioner** i Traivo One — en praktisk och effektiv modul som hanterar 5–20 fordon och täcker de allra flesta användningsfall. Systemet som helhet är dock mycket bredare än ruttoptimering och inkluderar fältpersonalhantering, kundhantering, arbetsordrar, rapportering och mycket mer.

### Kärnlöfte

> **"Ett komplett fältsystem som gör hela din fältverksamhet effektivare — från planering till leverans."**

Traivo One löser inte bara ruttplanering — det löser hela fältverksamhetens utmaningar:
- 🕐 **Sparad tid** — Automatisk ruttoptimering och smart resursplanering
- ⛽ **Lägre kostnader** — 15–25% kortare rutter, bättre resursutnyttjande
- 📦 **Fler leveranser/uppdrag** — Bättre utnyttjad kapacitet per dag
- 😊 **Nöjdare kunder** — Pålitliga tider, proaktiv kommunikation
- 📊 **Full insyn** — Realtidsöversikt av hela fältverksamheten
- 🔧 **Enterprise-kapacitet** — Skalbart system som växer med verksamheten

### Vad Traivo One ÄR

- ✅ Ett **enterprise-fältsystem** med bred funktionalitet
- ✅ Byggt för **små, medelstora och stora bolag**
- ✅ Ruttoptimering för **5–20 fordon** (praktisk, effektiv — täcker de flesta behov)
- ✅ Plattform för **hela fältverksamheten** — inte bara rutter
- ✅ **Skalbart** med tydlig uppgraderingsväg för avancerad ruttoptimering

### Vad Traivo One INTE är

Traivo One är inte ett specialiserat ruttoptimeringssystem för mycket stora flottor. För det finns Traivo Ruttplanering:
- ❌ Enterprise-ruttoptimering för 50–500 fordon (se [Traivo Ruttplanering](./TRAIVO_RUTTPLANERING.md))
- ❌ AI/ML-baserad realtids-ruttoptimering
- ❌ Avancerad EV-laddstrategiplanering
- ❌ Multi-objektiv Pareto-optimering av rutter

## 7. Ruttoptimering — Teknisk Specifikation

> **Kontext:** Ruttoptimering är en av flera moduler i Traivo One. Den är designad för att vara **praktisk, snabb och effektiv** — inte den mest avancerade optimeringen på marknaden, men tillräckligt bra för de allra flesta användningsfall med 5–20 fordon.

### 7.1 Varför NN + 2-opt istället för ALNS?

Det avancerade systemet (Traivo Ruttplanering) använder ALNS med 12 operator-kombinationer, simulated annealing, multi-objektiv kostnadsfunktion och k-means-klustring. För ruttoptimeringsmodulen i Traivo One har vi valt en enklare, mer effektiv approach:

| Faktor | NN + 2-opt i Traivo One | ALNS i Traivo Ruttplanering |
|--------|------------------------|---------------------------|
| **Målflotta** | 5–20 fordon | 10–500 fordon |
| **Svarstid** | < 2 sek (30 stopp) | 15–120 sek |
| **Lösningskvalitet** | ~85–90% av optimalt | ~95% av optimalt |
| **Komplexitet** | Låg — enkel att underhålla | Hög — kräver specialistkompetens |
| **Resursanvändning** | Minimal — körs på Replit | Kräver dedikerad server |
| **Tillräcklighet** | ✅ Mycket bra för 5–20 fordon | Nödvändig för 50+ fordon |

**Slutsats:** NN + 2-opt ger utmärkt resultat för Traivo One:s ruttoptimeringsbehov. Skillnaden mot ALNS är marginell vid < 20 fordon, men NN + 2-opt är dramatiskt snabbare och enklare.

### 7.2 Vald algoritm: Nearest-Neighbor + 2-opt

En tre-stegs-approach som balanserar kvalitet och hastighet:

#### Steg 1: Nearest-Neighbor med tidsfönster (Konstruktion)

Bygg initial lösning genom att alltid välja närmaste tillåtna stopp, med hänsyn till tidsfönster-brådska och kapacitet.

```typescript
function nearestNeighborWithTimeWindows(
  depot: Location,
  stops: Stop[],
  vehicle: Vehicle,
  startTime: Date
): Route {
  const route: Stop[] = [];
  const unvisited = [...stops];
  let currentLocation = depot;
  let currentTime = startTime;
  let currentLoad = 0;

  while (unvisited.length > 0) {
    const candidates = unvisited
      .filter(s => currentLoad + s.weight <= vehicle.capacity)
      .filter(s => canReachInTimeWindow(currentLocation, s, currentTime))
      .sort((a, b) => {
        // Urgency-viktad + avstånd som kombination
        const urgencyA = a.timeWindowEnd
          ? a.timeWindowEnd.getTime() - currentTime.getTime()
          : Infinity;
        const urgencyB = b.timeWindowEnd
          ? b.timeWindowEnd.getTime() - currentTime.getTime()
          : Infinity;
        const distA = haversine(currentLocation, a);
        const distB = haversine(currentLocation, b);
        return (urgencyA < 7200000 ? urgencyA * 0.001 : 0) + distA
             - (urgencyB < 7200000 ? urgencyB * 0.001 : 0) - distB;
      });

    if (candidates.length === 0) break;
    const next = candidates[0];
    route.push(next);
    currentTime = arrivalTime(currentLocation, next, currentTime);
    currentLoad += next.weight;
    currentLocation = next;
    unvisited.splice(unvisited.indexOf(next), 1);
  }

  return { stops: route, unassigned: unvisited };
}
```

**Tidskomplexitet:** O(n²) — utmärkt för n ≤ 80

#### Steg 2: 2-opt förbättring (Lokal sökning)

Förbättra lösningen iterativt genom att vända delsegment av rutten.

```typescript
function twoOptImprove(
  route: Stop[],
  depot: Location,
  maxIterations: number = 100
): Stop[] {
  let improved = true;
  let iterations = 0;

  while (improved && iterations < maxIterations) {
    improved = false;
    iterations++;
    for (let i = 0; i < route.length - 1; i++) {
      for (let j = i + 2; j < route.length; j++) {
        const currentCost = segmentCost(route, i, j, depot);
        const newRoute = twoOptSwap(route, i, j);
        const newCost = segmentCost(newRoute, i, j, depot);
        if (newCost < currentCost && timeWindowsFeasible(newRoute, depot)) {
          route = newRoute;
          improved = true;
        }
      }
    }
  }
  return route;
}
```

#### Steg 3: Multi-rutt tilldelning (5–20 fordon)

Fördela stopp på fordon med sektorbaserad klustring och optimera varje rutt individuellt.

```typescript
function assignToVehicles(
  stops: Stop[], vehicles: Vehicle[], depot: Location, startTime: Date
): Route[] {
  // A: Geografisk klustring med sektorindelning
  const clusters = sectorClustering(stops, depot, vehicles.length);
  // B: Tilldela kluster till fordon baserat på kapacitet
  const assignments = matchClustersToVehicles(clusters, vehicles);
  // C: Optimera varje rutt individuellt
  return assignments.map(({ cluster, vehicle }) => {
    const initial = nearestNeighborWithTimeWindows(depot, cluster, vehicle, startTime);
    const optimized = twoOptImprove(initial.stops, depot);
    return { vehicle, stops: optimized, unassigned: initial.unassigned };
  });
}
```

#### Sektorbaserad klustring

```typescript
function sectorClustering(stops: Stop[], depot: Location, k: number): Stop[][] {
  // Beräkna vinkel från depot till varje stopp, dela i k sektorer
  const withAngle = stops.map(s => ({
    stop: s,
    angle: Math.atan2(s.lat - depot.lat, s.lon - depot.lon)
  }));
  withAngle.sort((a, b) => a.angle - b.angle);
  const targetSize = Math.ceil(stops.length / k);
  const clusters: Stop[][] = [];
  for (let i = 0; i < k; i++) {
    clusters.push(
      withAngle.slice(i * targetSize, (i + 1) * targetSize).map(w => w.stop)
    );
  }
  return clusters;
}
```

### 7.3 Veckofördelningsalgoritm

```typescript
function distributeToWeek(
  deliveries: Delivery[], weekDays: Date[],
  vehicles: Vehicle[], preferences: WeekPreferences
): DayPlan[] {
  const dayPlans = weekDays.map(d => ({ date: d, stops: [] }));

  // 1. Fasta leveranser → rätt dag
  deliveries.filter(d => d.requiredDate).forEach(d => {
    const idx = weekDays.findIndex(w => sameDay(w, d.requiredDate));
    if (idx >= 0) dayPlans[idx].stops.push(d);
  });

  // 2. Återkommande → rätt veckodagar
  deliveries.filter(d => d.recurringDays?.length).forEach(d => {
    d.recurringDays.forEach(day => {
      const idx = weekDays.findIndex(w => w.getDay() === day);
      if (idx >= 0) dayPlans[idx].stops.push(d);
    });
  });

  // 3. Flexibla → fördela geografiskt & jämnt
  const flexible = deliveries.filter(d => !d.requiredDate && !d.recurringDays?.length);
  flexible.sort((a, b) => geoAngle(a) - geoAngle(b));
  flexible.forEach(delivery => {
    const bestDay = dayPlans
      .map((plan, idx) => ({
        idx,
        score: plan.stops.length * 10 + nearestDistInPlan(delivery, plan)
      }))
      .sort((a, b) => a.score - b.score)[0];
    dayPlans[bestDay.idx].stops.push(delivery);
  });

  return dayPlans;
}
```

## 17. Uppgraderingsväg & Integration

### 17.1 Ruttoptimering — Uppgraderingsväg

Traivo One:s ruttoptimering kan uppgraderas till Traivo Ruttplanering när behoven växer:

```
Traivo One-kund med 5–20 fordon
  → Ruttoptimering fungerar utmärkt med NN + 2-opt
  
Verksamheten växer → 30+ fordon, komplexa krav
  → Ruttoptimeringsmodulen ersätts/kompletteras med Traivo Ruttplanering
  
Integrerad lösning:
  Traivo One (fältsystem) + Traivo Ruttplanering (avancerad ruttmotor)
  = Bästa av båda världar
```

### 17.2 Vad som delas

- **Samma teknikstack** — React, Express, TypeScript, Drizzle, PostgreSQL
- **Kompatibla datamodeller** — Traivo One:s tabeller är en delmängd
- **Gemensam kartlösning** — Leaflet + OSRM
- **Samma API-mönster** — RESTful, Zod-validering

### 17.3 Migreringsscenarier

| Scenario | Lösning |
|----------|---------|
| Behöver fler fordon (20+) | Uppgradera ruttmodul till Traivo Ruttplanering |
| Behöver AI-baserad optimering | Lägg till Traivo Ruttplanering som backend-tjänst |
| Behöver realtidstrafik | Aktivera Traivo Ruttplanering-integration |
| Behöver EV-laddstrategi | Traivo Ruttplanering-modul |
| Nöjd med 5–20 fordon, vill ha mer fältfunktionalitet | Bygg ut Traivo One:s enterprise-moduler |

## 18. Framtidsvision

### 18.1 Traivo One — Utvecklingspotential

Traivo One har stor potential att växa som enterprise-fältsystem:

#### Kort sikt (6–12 månader)
- **Komplett fältpersonalhantering** — Schema, kompetens, certifikat
- **Arbetsordermodul** — Digitala arbetsordrar med checklists och formulär
- **Kundportal** — Kunder kan boka, följa och bekräfta leveranser/service
- **Integrationsplattform** — Webhooks, API-nycklar, tredjepartsintegrationer

#### Medellång sikt (12–24 månader)
- **AI-assisterad planering** — Smarta rekommendationer baserat på historik
- **Prediktiv underhållsplanering** — Fordon & utrustning
- **Avancerad rapportering** — Business Intelligence med trender och prognoser
- **Branschanpassning** — Specifika moduler för hemtjänst, fältservice, logistik

#### Lång sikt (24+ månader)
- **Traivo Ecosystem** — Traivo One som nav med plugins och moduler
- **Marketplace** — Tredjepartsutvecklare bygger på plattformen
- **Global skalning** — Multi-region, multi-språk, multi-valuta

### 18.2 Integration Traivo One ↔ Traivo Ruttplanering

Den ultimata visionen är en sömlös integration mellan systemen:

```
┌──────────────────────────────────────────────────────┐
│           TRAIVO INTEGRERAD PLATTFORM                  │
├──────────────────────────────────────────────────────┤
```
